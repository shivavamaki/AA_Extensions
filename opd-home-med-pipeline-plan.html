1The core difference: IPD vs OPD

The existing sheet is built for discharge (IPD). OPD is a different worklist and a different ArcusAir API, but — crucially — the same order-item shape, so almost the entire parse + render stack is reusable.

4Two decisions before I build

① How is the OPD orderid obtained?
Preferred: passively capture it from the workbench’s own dispense/search call in the XHR tap (zero extra clicks) — same pattern as medreconcileuid. Fallback: if the workbench doesn’t always fire it before the button is clicked, resolve the orderid from the selected-row DOM / Angular scope. I’ll build capture-first with the DOM resolver as backstop unless you know the orderid isn’t in that request.
② Which OPD orders go on the sheet?
The dispense/search response lists all items for the order (incl. refills). Options: (a) all dispensed items for the current order, (b) only take-home meds (exclude in-clinic/administered), (c) the pharmacist’s current dispense selection only. Default I’ll assume: (a) all items in the searched order, since that’s what “home medication” means for OPD — tell me if you want it filtered.
My recommendation: capture orderid in the tap (① preferred), render all items in the order (② a), reuse the entire IPD parse/translate/render stack via a thin OPD adapter. Minimal new surface, maximum consistency between the two sheets. Confirm or adjust these two, and I’ll build it.

Once confirmed I’ll implement in this order: XHR-tap capture → server fetch/route/adapter → detection gate + button → OPD header variant, verifying each against a live payload before moving on (no assumptions — same discipline as the last few changes). The vertical button-group CSS ships in the same batch.
