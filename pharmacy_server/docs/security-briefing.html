02ข้อมูลไหลยังไง

ข้อมูลคนไข้ทุกอย่างต้นทางมาจาก ArcusAir เราแค่อ่านมา แล้วเก็บสำเนาไว้ให้เครื่องอื่นเห็นคิวเดียวกัน ไม่มีอะไรออกนอกเครือข่ายโรงพยาบาล

เก็บอะไรไว้บ้าง

เก็บอะไรกี่ไฟล์ขนาดมีอะไรอยู่ข้างในลบเมื่อไหร่

เพิ่งแก้ไป — ตอนนี้ patients/ hmr/ hmq/ ตั้งไว้ เก็บ 60 วัน แล้วลบอัตโนมัติ รันทุกคืน 23:00 พร้อมงาน nightly เดิม (purge_expired_records() — อ่าน updatedAt ของแต่ละ record ถ้าอ่านไม่ได้จะเก็บไว้ ไม่เดา)

ทดสอบแบบ dry-run แล้ว: จะลบ 621 record ที่เกิน 60 วัน (patients 595, hmr 26)

60 วันเป็นตัวเลขที่เราตั้งเอง ถ้าควรสั้นหรือยาวกว่านี้ บอกได้ แก้ตัวเลขเดียว

Token กับ password จัดการยังไง

  • Password ของ portal — PBKDF2-HMAC-SHA256 + salt, มี 3 account
  • ArcusAir token — extension จะ capture incus-token ของเภสัชกรที่ login อยู่ มาให้ server ดึง report แทน เก็บไว้ไม่เกิน 24 ชม. แล้วใช้ไม่ได้
  • ไม่มี service account — server ทำงานได้เฉพาะตอนที่มี session ของคนจริง ๆ อยู่

Log เก็บอะไรจริง ๆ

กดดูตัวอย่างจริงได้ (ปิดข้อมูลบางส่วนแล้ว)

ข้อจำกัดที่ต้องบอกตรง ๆ — log เก็บเฉพาะเหตุผิดปกติกับ event การทำงาน ไม่ได้เก็บว่าใครเปิดดูอะไรสำเร็จบ้าง แปลว่าตอนนี้ตอบไม่ได้ว่า "ใครเปิดดูคนไข้รายนี้"

03ความเสี่ยงที่เจอ

เราตรวจเองแล้วเอามาบอกก่อน ไม่ได้รอให้ตรวจเจอ กดที่หัวข้อเพื่อดูรายละเอียด

ยังค้าง 2 ข้อ   แก้แล้ว 7 ข้อ

สิ่งที่อยากขอจากทีม Security

  1. 60 วันโอเคไหม — เราตั้งเองสำหรับ patients/ hmr/ hmq/ ถ้าควรสั้นหรือยาวกว่านี้บอกได้
  2. GitHub — เปลี่ยน password แล้ว แต่ history ลบไม่ได้ ต้อง rewrite หรือแจ้งเป็น disclosure ไหม
  3. TLS — ขอ certificate สำหรับ host ภายในได้ไหม
  4. ยังต้องทำอะไรอีก — มีอะไรที่เรายังมองไม่เห็น ช่วยชี้ให้หน่อย
